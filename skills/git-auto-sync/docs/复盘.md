## 主要问题与解决

- 初版会混入用户预暂存改动：改为发现预暂存内容即停止，不重写索引。
- 同文件已有改动无法可靠自动拆分：要求 Codex 修改前检查，`--allow-dirty` 仅用于确认本任务改动。
- 裸 `git push` 和短 refspec 会继承重定向或强推配置：首次及后续推送均使用完整非强制 refspec。
- 敏感目录可能先被暂存：先用 Git 展开候选路径，再执行暂存。
- Windows 中文输出和 bare 远程默认分支导致测试失真：统一 UTF-8，并显式设置远程 `HEAD=main`。

## 2026-11-10 优化复盘

- 触发原因：真实使用中遇到 Git 全局代理端口从 20890 漂移到 20891，旧执行器只能提示核对端口，无法指出实际可用端口。
- 代码改动按六个独立提交推进：超时可配置、认证误判收窄、porcelain -z 路径解析、内容密钥扫描、push 错误分类、回环端口探测。每个提交先写失败测试再实现，测试从 17 个增加到 40 个。
- 关键取舍：错误归类函数保持纯函数，不做任何 Git 写操作；push 失败时只报告并保留本地 commit。端口探测限定回环常见端口，不做外网扫描，也不自动改全局代理。
- 测试夹具踩坑：本地文件协议远程忽略 http.proxy，dumb HTTP 假服务器无法复刻真实 GitHub 的 401 文本。最终把分类正确性交给纯函数测试，集成测试只锁定“push 失败必须保留本地提交”这个可稳定复现的契约。
